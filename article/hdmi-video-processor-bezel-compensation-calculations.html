HDMI Video Processor Bezel Compensation Calculations

This article provides an overview of the bezel compensation calculations performed by an HDMI multi-display video processor. When multiple screens form a video wall, the physical frames (bezels) break image continuity. Bezel compensation mathematically accounts for this physical gap by calculating virtual, hidden pixels between monitors, ensuring diagonal lines and continuous graphics appear straight and correctly proportioned across the entire display array.

1. Determining Pixel Density (Pixels Per Dimension)

Before an HDMI processor can map pixels across gaps, it must translate the physical bezel measurements into a pixel equivalent. The processor requires the active display dimensions and its native pixel resolution to find the pixel density:

  • Horizontal Pixel Pitch (\(P_h\)): Active Width (mm) / Native Horizontal Resolution
  • Vertical Pixel Pitch (\(P_v\)): Active Height (mm) / Native Vertical Resolution

Alternatively, the processor computes Pixels Per Millimeter (PPM):

  • \(\text{PPM}_h = \text{Native Horizontal Resolution} / \text{Active Width (mm)}\)
  • \(\text{PPM}_v = \text{Native Vertical Resolution} / \text{Active Height (mm)}\)

2. Calculating Virtual Gap Pixels

Once pixel density is established, the processor calculates how many pixels are physically missing between two adjacent viewable areas. The physical gap (\(G\)) is the sum of the adjacent bezels (e.g., Right Bezel of Display A + Left Bezel of Display B):

  • Horizontal Gap Pixels (\(V_{\text{gap\_h}}\)): \(G_h \times \text{PPM}_h\)
  • Vertical Gap Pixels (\(V_{\text{gap\_v}}\)): \(G_v \times \text{PPM}_v\)

These calculated values represent the "concealed" pixels that the viewer would see if the screens had no bezels.

3. Establishing the Virtual Canvas Resolution

The processor then constructs an expanded internal coordinate canvas that encompasses both the active screen regions and the calculated virtual gaps. For an \(M \times N\) display grid:

  • Total Virtual Width:
    \[\text{Canvas}_W = (M \times \text{Native}_X) + ((M - 1) \times V_{\text{gap\_h}})\]
  • Total Virtual Height:
    \[\text{Canvas}_H = (N \times \text{Native}_Y) + ((N - 1) \times V_{\text{gap\_v}})\]

4. Input Scaling and Aspect Ratio Preservation

The incoming HDMI video stream is mapped onto this enlarged virtual canvas. The processor calculates scaling factors (\(S_x\) and \(S_y\)) to stretch or fit the input resolution to the canvas dimensions:

  • \(S_x = \text{Canvas}_W / \text{Input}_W\)
  • \(S_y = \text{Canvas}_H / \text{Input}_H\)

By scaling the image across the total virtual area rather than just the visible screen pixels, geometry is preserved, preventing the image from appearing horizontally or vertically compressed behind the frames.

5. Viewport Coordinate Mapping and Cropping

Finally, the video processor extracts the distinct video signals for each physical HDMI output port. It computes the active sub-frame bounding box for a display located at column \(c\) and row \(r\) (using zero-based indexing):

  • \(X_{\text{start}}\): \(c \times (\text{Native}_X + V_{\text{gap\_h}})\)
  • \(X_{\text{end}}\): \(X_{\text{start}} + \text{Native}_X\)
  • \(Y_{\text{start}}\): \(r \times (\text{Native}_Y + V_{\text{gap\_v}})\)
  • \(Y_{\text{end}}\): \(Y_{\text{start}} + \text{Native}_Y\)

The processor crops the region bounded by \([X_{\text{start}}, Y_{\text{start}}]\) to \([X_{\text{end}}, Y_{\text{end}}]\) and outputs it to the respective display. The calculated \(V_{\text{gap\_h}}\) and \(V_{\text{gap\_v}}\) pixel regions are masked out, creating the natural illusion that the image is continuing seamlessly behind the display bezels.
