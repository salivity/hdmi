EDID Modifications for Custom HDMI Resolutions

Extended Display Identification Data (EDID) is a standardized metadata format that displays use to communicate their display capabilities to a host graphics card. By editing the base EDID data blocks and CEA/CTA-861 extension blocks, you can override standard timing limits, bypass driver validation, and force a GPU to output non-standard resolutions and refresh rates over HDMI. This process involves altering Detailed Timing Descriptors, expanding pixel clock limits, and adjusting Video Specific Data Blocks.

Detailed Timing Descriptors (DTDs)

The primary method for introducing non-standard resolutions is editing or injecting Detailed Timing Descriptors (DTDs). Located within bytes 54–125 of the base EDID block or inside the CTA-861 extension block, each DTD is an 18-byte structure that explicitly maps display timings:

  • Pixel Clock: Set the clock frequency (in increments of 10 kHz) to ensure the graphics card outputs the exact data rate needed.
  • Active Pixels and Blanking: Define horizontal active pixels (e.g., 2560) and vertical active lines (e.g., 1080), along with their respective blanking intervals (front porch, sync pulse, and back porch).
  • Timings Standards: Utilizing Coordinated Video Timings with Reduced Blanking (CVT-RB or CVT-RB2) inside the DTD minimizes blanking intervals, keeping custom high resolutions or ultra-wide formats within HDMI TMDS bandwidth constraints.

Modifying the CTA-861 Extension Block

HDMI connections rely heavily on CTA-861 extension blocks to advertise features beyond standard VESA modes. To permit non-standard resolutions:

  • Add CTA DTDs: Modern operating systems often prioritize DTDs stored in the CTA-861 extension over those in the base block. Injecting your custom parameters into the extension’s data block collection ensures the GPU driver exposes the mode to the OS.
  • Remove Incompatible SVDs: Deleting conflicting Short Video Descriptors (SVDs) prevents the display driver from automatically defaulting to a standard 1080p or 4K profile.

HDMI Vendor-Specific Data Block (VSDB)

HDMI features are regulated by the HDMI 1.4b and HDMI Forum (HF) VSDB structures found in the extension block:

  • Max TMDS Clock: The HDMI 1.4 VSDB contains an entry specifying the maximum supported TMDS character rate (in 5 MHz increments). Increasing this value (up to 340 MHz for HDMI 1.4 limits) prevents graphics drivers from blocking high-bandwidth custom resolutions.
  • HF-VSDB for HDMI 2.0+: For bandwidth beyond 340 MHz (up to 600 MHz), modifying or adding an HDMI Forum VSDB with the "Max_TMDS_Character_Rate" set to 600 MHz and enabling SCDC (Status and Control Data Channel) flags permits resolutions like ultrawide 3840x1600 or 5120x1440.

Checksum Validation

The final byte (byte 127 for the base block and byte 255 for the extension block) is a checksum. The sum of all 128 bytes in each block modulo 256 must equal zero. When any value inside the DTDs or data blocks is altered, the checksum byte must be recalculated; otherwise, graphics drivers will mark the EDID as corrupted and fall back to safe VGA resolutions (e.g., 640x480 or 1024x768).

Implementation Methods

  • Software Overrides: Tools like Custom Resolution Utility (CRU) write modified EDID blocks directly into the Windows Registry under the active display's hardware ID. On Linux, custom EDID binaries are loaded via kernel parameters using the drm.edid_firmware flag.
  • Hardware Interposers: Hardware HDMI EDID emulators or inline programmatic "ghost plugs" can have modified EDID binaries flashed directly to their onboard EEPROM via I²C, presenting the modified resolution parameters directly to the GPU's HDMI physical layer.
