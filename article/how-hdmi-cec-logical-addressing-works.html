How HDMI CEC Logical Addressing Works

HDMI Consumer Electronics Control (CEC) enables interconnected home theater components to communicate over a single control line, using a specialized addressing protocol to ensure messages reach the correct hardware. This article explains the fundamentals of HDMI CEC logical addressing, how it distinguishes device roles across a shared bus, and the step-by-step polling process a source device uses to claim its unique device ID upon connecting to an HDMI network.

What is HDMI CEC Logical Addressing?

HDMI devices maintain two types of addresses: a physical address and a logical address. While the physical address reflects the device's physical position in the HDMI topology (derived via EDID and structured in hierarchical notation such as 1.0.0.0), the logical address defines the device's functional role.

The CEC protocol allocates 16 discrete logical addresses, numbered from 0 to 15:

  • 0: TV
  • 1, 2, 9: Recording Devices (e.g., PVRs, DVRs)
  • 3, 6, 7, 10: Tuner Devices
  • 4, 8, 11: Playback Devices (e.g., Blu-ray players, streaming consoles)
  • 5: Audio System (e.g., AV receivers, soundbars)
  • 12, 13: Reserved for future extension
  • 14: Specific Use / TV 2
  • 15: Unregistered (when used as an initiator) / Broadcast (when used as a destination)

Because the CEC line is a shared, single-wire bus, each active device must hold a distinct logical address to prevent command collisions and allow targeted device-to-device communication.

How a Source Device Claims Its Logical Address

When a source device (such as a media streamer or disc player) boots up or detects a hot-plug event, it cannot immediately assume a logical address. It must dynamically claim an address through a standardized discovery process known as address allocation:

  1. Determine Device Category: The device identifies its functional type to select an ordered list of candidate addresses defined by the HDMI CEC specification. For instance, a playback source prioritizes address 4 (Playback 1), followed by 8 (Playback 2), and then 11 (Playback 3).

  2. Send a Polling Message: The device sets its temporary initiator address to the candidate address it wishes to test, and sets the destination address to that same value. It transmits this <Polling Message> across the CEC line.

  3. Check for Acknowledgment (ACK):

    • If an ACK is received: Another active component is already occupying that logical address. The probing device abandons that address and repeats the polling process with the next candidate in its category list.
    • If a NACK (No Acknowledge) occurs: No hardware asserts the ACK bit on the bus, signaling that the candidate address is vacant.

  4. Acquire the Address: Once the polling message goes unacknowledged, the source device immediately assigns that logical address to itself. From this point forward, it will acknowledge all incoming traffic addressed to that ID and report its physical-to-logical address mapping using the <Report Physical Address> broadcast command.

  5. Fallback to Unregistered: If all candidate addresses for its category generate an ACK (meaning all available slots are occupied), the device must set its logical address to 15 (Unregistered). An unregistered device can still transmit broadcast commands or receive global notifications, but it cannot receive directed CEC commands.
