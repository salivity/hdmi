How HDMI CEC Transmits Binary Data Frames

The High-Definition Multimedia Interface Consumer Electronics Control (HDMI CEC) protocol enables interconnected audiovisual devices to communicate over a single shared physical line using an open-drain architecture. This article explains the physical and electrical mechanisms that allow a device to pull the CEC line low to generate binary data frames, detailing the open-collector circuitry, pulse-width timing characteristics for logical bits, and the line arbitration process.

The Open-Drain Physical Layer

HDMI CEC operates over Pin 13 of the standard HDMI connector. It is a single-wire, bidirectional bus referenced to ground (Pin 17). The electrical backbone of CEC is an open-drain (or open-collector) configuration:

  • Idle State (Logic High): The bus is not actively driven high by a transmitter. Instead, a passive pull-up resistor (typically connected to a +3.3V rail inside the devices) holds the CEC line at a nominal 3.3V when no device is actively signaling.
  • Active State (Logic Low): To transmit, a device turns on an internal N-channel MOSFET or bipolar junction transistor connected between Pin 13 and Ground. This shunts the line voltage to 0V, pulling the bus low against the pull-up resistor.

Because devices only ever pull the line to ground and never drive it high, multiple devices can be connected to the same wire simultaneously without risking electrical shorts.

Pulse-Width Modulation and Bit Encoding

CEC does not use traditional high-or-low state logic (such as standard NRZ UART) where voltage levels directly represent continuous values. Instead, it uses a pulse-width modulated (PWM) scheme where every single bit begins with the line being pulled low. The duration of time the line remains pulled low determines the type of bit being transmitted.

Each standard data bit period lasts approximately 2.4 milliseconds (nominal) and adheres to strict timing windows:

  • Logic '0': The transmitting device pulls the line low for a long duration—nominally 1.5 ms (valid window: 1.3 ms to 1.7 ms)—and then releases the transistor, allowing the pull-up resistor to return the line high for the remaining 0.9 ms of the 2.4 ms cycle.
  • Logic '1': The transmitting device pulls the line low for a short duration—nominally 0.6 ms (valid window: 0.4 ms to 0.8 ms)—and then releases the line, allowing it to float high for the remaining 1.8 ms of the cycle.
  • Start Bit: Before any data frame begins, a distinctive Start Bit synchronizes the bus. The line is pulled low for 3.7 ms and then released to high for 0.8 ms, creating a unique 4.5 ms waveform that cannot be confused with regular data bits.

Receiving devices sample the bus line approximately 1.05 ms after the falling edge. If the line is still low at the sampling point, the receiver reads a 0; if the line has already returned high, the receiver reads a 1.

Data Frame Assembly

A complete CEC transmission consists of sequential 10-bit blocks that follow the initial Start Bit:

  1. Information Bits (Bits 0–7): Eight bits carrying either address headers or command payloads (opcodes and operands).
  2. End of Message (EOM, Bit 8): A single bit indicating whether another data block follows (0) or if this is the final block in the frame (1).
  3. Acknowledge (ACK, Bit 9): A handshaking mechanism where the transmitter sends a nominal 1 by pulling low for only 0.6 ms and releasing the line. If a targeted receiver has successfully validated the previous bits, the receiver actively overrides the bus by pulling it low during the sample window, converting the 1 into a 0 to signal acknowledgment.

Wired-AND Bus Arbitration

Because the line defaults to high and can only be actively pulled to 0V, the physical bus functions as a "wired-AND" logic gate. A pulled-low state (0) always overrules a released high state (1).

If two devices attempt to transmit at the exact same moment, both will synchronize on their Start Bits. As they output their address bytes, they monitor the bus state while releasing their pull-down transistors. If Device A attempts to send a 1 (releasing the line at 0.6 ms) but Device B is sending a 0 (continuing to pull low until 1.5 ms), Device A detects that the line remains low despite its own release. Device A recognizes that it has lost arbitration, immediately ceases transmission, and switches to receiver mode without corrupting the message transmitted by Device B.
