How HDMI ALLM Disables TV Post-Processing Filters

HDMI Auto Low Latency Mode (ALLM) is an HDMI 2.1 feature that instructs a television to automatically switch to its fastest, lowest-latency display preset—commonly referred to as Game Mode—whenever a compatible console or graphics card sends an active gaming signal. By transmitting specific signaling metadata within the digital video stream, ALLM bypasses latency-heavy post-processing filters such as frame interpolation, dynamic noise reduction, and motion smoothing without requiring the user to navigate the television’s settings menus. This article breaks down the underlying communication protocol, the data packets responsible for the trigger, and how the television’s internal processor physically disengages these filters.

1. Capability Discovery via EDID

Before ALLM can send any commands, the source device (such as a PlayStation 5, Xbox Series X, or PC) must confirm that the display supports the feature. This initial handshake occurs via the television’s Extended Display Identification Data (EDID).

Within the EDID, the television hosts an HDMI Forum Vendor-Specific Data Block (HF-VSDB). If the television supports low-latency switching, it sets a specific ALLM support bit inside this block to active. Once read by the source device during the initial HDMI handshake, the source knows it has permission to issue latency commands.

2. The Command Packet: HDMI Forum VSIF

When a user launches a game, the source device modifies the video stream metadata by transmitting an HDMI Forum Vendor-Specific InfoFrame (HF-VSIF). InfoFrames are secondary data packets injected into the vertical and horizontal blanking intervals between individual video frames.

Within the HF-VSIF payload, there is a dedicated field containing the ALLM_Mode bit:

  • Setting the bit to 1 commands the television to engage Auto Low Latency Mode.
  • Setting the bit to 0 commands the television to return to standard picture processing.

Because this packet travels directly within the active HDMI auxiliary data stream, the signal arrives synchronously with the video data, ensuring instantaneous detection by the television's HDMI receiver chip.

3. Display Processor Reaction and Filter Disengagement

Once the television's HDMI receiver decodes the ALLM_Mode = 1 state from the HF-VSIF, it triggers an interrupt in the television’s System on Chip (SoC) or primary video scalar.

Under normal viewing conditions (such as watching movies), the video scalar routes the incoming pixel stream through multiple internal frame buffers to apply intensive post-processing algorithms. These filters include:

  • Motion Estimation, Motion Compensation (MEMC): Synthesizes artificial intermediate frames to reduce perceived judder, requiring several frames of buffering and adding 40–100 milliseconds of input lag.
  • Spatial and Temporal Noise Reduction: Analyzes sequential frames to identify and scrub film grain or compression artifacts.
  • Edge Enhancement and Dynamic Contrast: Enhances sharpness and local illumination using multi-pass computational filters.

When the ALLM command is acknowledged, the television firmware directly modifies the video processing pipeline. It reconfigures the internal register states of the video scalar to bypass these frame buffers entirely. The signal is redirected along a "fast path" that strips out computationally expensive algorithms and routes the digital pixel data straight to the timing controller (T-CON), which directly drives the display panel.

4. Reversion to Standard Latency

When the user exits the game or switches to a media playback application (such as Netflix or a Blu-ray player), the source device immediately updates the HF-VSIF, flipping the ALLM_Mode bit back to 0. The television's SoC registers the removal of the flag, rebuilds the full processing pipeline, and safely restores the user’s preferred cinematic picture modes and image enhancement filters without interrupting the core video display signal.
