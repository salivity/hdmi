How HDMI Sinks Report VIC Numbers via EDID

An HDMI sink, such as a monitor or TV, communicates its supported display capabilities to a computer using Extended Display Identification Data (EDID) read over the I2C-based Display Data Channel (DDC). While the base EDID defines legacy display parameters and detailed timing descriptors, Video Identification Codes (VICs) are communicated specifically through CTA-861 (formerly CEA-861) extension blocks. These standardized numerical codes inform the graphics driver of the exact video formats, resolutions, aspect ratios, and refresh rates the display natively supports without needing custom timing calculations.

The EDID Handshake Process

When an HDMI display connects to a computer, it pulls the Hot Plug Detect (HPD) line high (to +5V). In response, the host computer queries the display’s EDID memory via the DDC bus. The sink responds by transmitting its standard 128-byte base EDID block, followed by one or more 128-byte extension blocks. To signal HDMI compliance and specific digital video capabilities, the display includes a CTA-861 Extension Block indicated by an extension tag value of 0x02.

The CTA-861 Video Data Block

Within the CTA-861 extension block lies the Data Block Collection (DBC). The sink categorizes its multimedia capabilities—such as audio, vendor-specific info, and video—into discrete blocks identified by 3-bit tag codes.

Supported VIC numbers are packaged inside the Video Data Block (VDB), designated by Tag Code 2 (010 in binary). The payload of the VDB consists of a sequential list of one-byte entries known as Short Video Descriptors (SVDs).

Structure of a Short Video Descriptor (SVD)

Each byte in the Video Data Block represents a single SVD and directly specifies a supported VIC. The 8 bits of each SVD byte are structured as follows:

  • Bit 7 (Native Flag): Indicates whether the video mode is the display's native resolution (1 for native, 0 for non-native).
  • Bits 6–0 (VIC Value): A 7-bit integer mapping directly to a standard CTA-861 Video Identification Code ranging from 1 to 127.

For example, a byte value of 0x90 in the VDB breaks down into binary 10010000. Bit 7 is 1, marking it as a native format, and the remaining 7 bits equal 0010000 (decimal 16). In the CTA-861 specification, VIC 16 defines a 1920x1080p resolution at a 60 Hz refresh rate with a 16:9 aspect ratio.

Handling Extended VICs (128–255)

The standard 7-bit field limits direct SVD values to VIC 127. Because modern high-resolution formats—such as 4K and 8K at varying frame rates—require codes above 127, modern sinks use the Extended Video Data Block introduced in CTA-861-F.

To communicate VICs between 128 and 255:

  1. The sink includes a Use Extended Tag data block (Tag Code 7).
  2. It sets the extended tag code to 0x00 (Video Format Preference Data Block) or uses modern Short Video Descriptors under extended timing structures.
  3. The computer’s graphics stack interprets these 8-bit extended values to recognize newer Ultra HD formats (such as VIC 97 for 3840x2160p at 60 Hz or VIC 218 for 8K formats).

Computer Interpretation

Once the computer's GPU driver parses the CTA extension block, it extracts all listed VICs from the SVD entries. The driver correlates each number with its internal CTA-861 timing database, identifying the exact horizontal and vertical pixel counts, front and back porches, sync pulses, and pixel clock frequencies. The operating system then populates the display settings menu with matching, validated resolutions and refresh rates.
