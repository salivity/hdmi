HDMI 2.0 Receiver Eye Height and Width Specs

This article provides a direct overview of the physical layer eye diagram specifications for an HDMI 2.0 receiver (Sink). Operating at signaling rates up to 6.0 Gbps per channel, HDMI 2.0 requires compliant receivers to correctly decode signals under severe channel loss and jitter. Below are the precise minimum eye height and eye width requirements, along with the operational context in which these measurements are evaluated.

Minimum Specifications

For HDMI 2.0 data rates exceeding 3.4 Gbps and up to 6.0 Gbps per TMDS data channel, the receiver eye mask defines the following minimum limits:

  • Minimum Eye Height (\(EH_{min}\)): 150 mV (differential peak-to-peak)
  • Minimum Eye Width (\(EW_{min}\)): 0.40 UI (Unit Interval)

At the maximum HDMI 2.0 transmission rate of 6.0 Gbps, one Unit Interval (1 UI) equals approximately 166.67 picoseconds (ps). Consequently, a minimum eye width of 0.40 UI corresponds to an absolute time opening of roughly 66.67 ps.

Test Point and Equalization Context (TP2_EQ)

Unlike earlier HDMI standards where compliance was verified directly at the receiver input pins (Test Point 2, or TP2), high-frequency attenuation over standard HDMI cables at 6.0 Gbps causes the physical signal at TP2 to be completely closed.

To account for this, the HDMI 2.0 specification defines the receiver minimum eye requirements at TP2_EQ:

  1. Reference Equalization: The input signal from the worst-case compliant cable is passed through a mathematically standardized Reference Cable Equalizer (a Continuous Time Linear Equalizer, or CTLE model).
  2. Post-Equalizer Measurement: The resulting eye diagram must meet or exceed the 150 mV height and 0.40 UI width inside the receiver's internal physical layer circuitry.

Jitter Tolerance

The eye width requirement directly corresponds to the receiver's jitter tolerance specifications. With an eye width requirement of 0.40 UI, the HDMI 2.0 sink device must be capable of tolerating up to 0.60 UI of Total Jitter (TJ) composed of both deterministic jitter (DJ) and random jitter (RJ) while maintaining an error-free link (a bit error rate of \(10^{-9}\) or better).
