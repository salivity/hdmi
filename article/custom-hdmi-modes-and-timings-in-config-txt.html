Custom HDMI Modes and Timings in config.txt

Configuring custom HDMI modes on a Raspberry Pi allows you to drive non-standard displays, ultra-wide panels, and specialized LCD or CRT hardware that standard EDID handshakes fail to detect. By modifying the config.txt file located in the boot partition, you can bypass automatic resolution negotiation and force the GPU to output explicit display parameters. This guide details the primary parameters required to enable custom resolutions, use Coordinated Video Timings (CVT), and define raw, micro-adjusted video timings.

Essential Base Settings

To enable any custom video mode, two foundational parameters must be set in config.txt:

  • hdmi_group=2: Sets the display mode group to DMT (Display Monitor Timings), the standard computer monitor format, which is required for custom resolutions.
  • hdmi_mode=87: Indicates a custom HDMI mode defined either by hdmi_cvt or raw hdmi_timings. Without setting this value, custom parameters are ignored.

Automated Timings with hdmi_cvt

The hdmi_cvt directive uses the VESA Coordinated Video Timings standard to calculate blanking intervals and pixel clocks automatically based on your desired resolution.

The syntax is:

hdmi_cvt=<width> <height> <framerate> <aspect> <margins> <interlace> <rb>

The parameters include:

  • width: Horizontal resolution in pixels (e.g., 1024).
  • height: Vertical resolution in lines (e.g., 600).
  • framerate: Target refresh rate in Hz (e.g., 60).
  • aspect: Aspect ratio selection: 1 for 4:3, 2 for 14:9, 3 for 16:9, 4 for 5:4, 5 for 16:10, or 6 for non-standard.
  • margins: Overscan margins: 0 (disabled) or 1 (enabled).
  • interlace: Scan mode: 0 (progressive) or 1 (interlaced).
  • rb: Reduced blanking: 0 (standard blanking, typical for CRTs) or 1 (reduced blanking, typical for modern LCDs to save bandwidth).

Precise Hardware Control with hdmi_timings

When driving raw panels, arcade monitors, or display controllers with fixed, non-standard blanking windows, hdmi_timings replaces hdmi_cvt to give you complete control over the video signal.

The syntax requires 17 values separated by spaces:

hdmi_timings=<h_active_pixels> <h_sync_polarity> <h_front_porch> <h_sync_pulse> <h_back_porch> <v_active_lines> <v_sync_polarity> <v_front_porch> <v_sync_pulse> <v_back_porch> <v_sync_offset_a> <v_sync_offset_b> <pixel_rep> <frame_rate> <interlaced> <pixel_freq> <aspect_ratio>

The 17 positional arguments correspond to:

  1. h_active_pixels: Horizontal visible resolution.
  2. h_sync_polarity: Invert horizontal sync (0 for active low, 1 for active high).
  3. h_front_porch: Horizontal front porch in pixel clocks.
  4. h_sync_pulse: Horizontal sync pulse width in pixel clocks.
  5. h_back_porch: Horizontal back porch in pixel clocks.
  6. v_active_lines: Vertical visible resolution.
  7. v_sync_polarity: Invert vertical sync (0 for active low, 1 for active high).
  8. v_front_porch: Vertical front porch in lines.
  9. v_sync_pulse: Vertical sync pulse width in lines.
  10. v_back_porch: Vertical back porch in lines.
  11. v_sync_offset_a: Vertical sync offset A (normally set to 0).
  12. v_sync_offset_b: Vertical sync offset B (normally set to 0).
  13. pixel_rep: Pixel repetition count (normally 0).
  14. frame_rate: Refresh rate in Hz (used as metadata; actual refresh rate depends on the pixel clock).
  15. interlaced: Scan format (0 for progressive, 1 for interlaced).
  16. pixel_freq: Pixel clock frequency in Hertz (e.g., 32000000 for 32 MHz).
  17. aspect_ratio: Display aspect ratio index (1 = 4:3, 2 = 14:9, 3 = 16:9, 4 = 5:4, 5 = 16:10, 6 = 15:9, 7 = 21:9, 8 = 64:27).

Supporting Configuration Parameters

Custom modes often require additional flags to prevent the Raspberry Pi from falling back to default safe modes:

  • hdmi_force_hotplug=1: Forces the HDMI output to remain active even if no display handshake (hotplug detect) is present.
  • hdmi_drive=2: Forces standard HDMI output mode (with audio), whereas 1 forces pure DVI output (no audio transmission).
  • hdmi_ignore_edid=0xa5000080: Completely ignores the monitor's built-in EDID data to prevent conflicting timing requests.
  • disable_overscan=1: Prevents the GPU from scaling or applying black borders around the custom-defined frame boundaries.
  • config_hdmi_boost: Increases the drive strength of the HDMI signal (values range from 0 to 11, where default is usually 5), helpful for signal degradation across long cables or passive converters.
