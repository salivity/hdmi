How DisplayPort Dual-Mode Outputs Native HDMI

DisplayPort Dual-Mode, commonly designated as DP++, is a standard that enables a DisplayPort source to detect an HDMI display and automatically transmit native HDMI signals through the existing connector. By switching the graphics processing unit's (GPU) internal transmitter to output HDMI-compliant video and relying on an inexpensive passive adapter for electrical level shifting, DP++ bridges the gap between different display standards without requiring complex active signal conversion.

Understanding DisplayPort Dual-Mode (DP++)

DisplayPort and HDMI use fundamentally different transmission architectures. Native DisplayPort transmits data in micro-packets across fixed-frequency differential pairs, similar to Ethernet or USB. Conversely, HDMI uses Transition-Minimized Differential Signaling (TMDS), which streams uncompressed pixel data continuously alongside a dedicated clock signal.

Under standard conditions, a DisplayPort output cannot communicate with an HDMI display. DisplayPort Dual-Mode solves this by building secondary HDMI (and single-link DVI) transmission capabilities directly into the GPU's display controller. When a DP++ port is used, the GPU does not convert DisplayPort data into HDMI; instead, it ceases transmitting DisplayPort data altogether and generates native TMDS signals directly from its internal PHY (physical layer).

The Detection Mechanism: Cable Adapter Detect

The transition from DisplayPort mode to HDMI mode is triggered automatically using hardware detection:

  1. Adapter Insertion: When you plug a passive DisplayPort-to-HDMI adapter into a DP++ port, the adapter interfaces with specific pins on the DisplayPort connector.
  2. CAD Pin Pull-Down: Pin 13 on the standard DisplayPort connector functions as the Cable Adapter Detect (CAD) pin (or Config2). A passive HDMI adapter contains a pull-down resistor that pulls the voltage on this pin low.
  3. GPU State Change: The graphics card’s display controller monitors the CAD pin. Upon detecting the low logic state, the GPU identifies that a passive HDMI adapter is present.
  4. AUX to DDC Remapping: The GPU reconfigures the bidirectional DisplayPort Auxiliary (AUX) channel pins (Pins 5 and 7) to act as an I2C-based Display Data Channel (DDC). This allows the computer to read the monitor’s Extended Display Identification Data (EDID) using standard HDMI protocols.

The Role of the Passive Adapter

Although the GPU generates the native TMDS signaling protocol, a passive adapter is still required between the graphics card and the HDMI cable to resolve electrical differences.

  • AC to DC Coupling: DisplayPort uses AC-coupled differential signaling with a typical operating voltage around 3.3V and low peak-to-peak voltage swings. HDMI relies on DC-coupled signals terminated to a 3.3V rail, resulting in a higher differential voltage.
  • Level Shifting: The passive DP++ adapter contains a simple hardware level shifter. This component buffers the signals and adjusts the DC bias and voltage levels to ensure they conform strictly to HDMI physical layer specifications.
  • Pin Remapping: The adapter physically routes the DisplayPort main link lanes to the corresponding HDMI TMDS data lanes and maps the DisplayPort AUX lines to the HDMI DDC and Hot Plug Detect (HPD) lines.

Because the GPU performs all protocol encoding natively, the passive adapter does not require an expensive digital signal processor (DSP), making it simpler, cooler, and less expensive than an active converter.

Dual-Mode Types and Bandwidth Limitations

DP++ is categorized into two main standards, which govern maximum resolution and refresh rates:

  • Type 1 DP++: Limited to a maximum TMDS clock frequency of 165 MHz. This provides sufficient bandwidth for resolutions up to 1920×1200 at 60 Hz or standard 1080p video.
  • Type 2 DP++: Increases the maximum TMDS clock frequency to 300 MHz (introduced alongside DisplayPort 1.2). This standard allows passive adapters to carry resolutions up to 4K (3840×2160) at 30 Hz or 1080p at higher refresh rates.

If a display configuration demands bandwidth beyond Type 2 capabilities—such as 4K at 60 Hz (which requires a 600 MHz TMDS clock under HDMI 2.0) or HDMI 2.1 Fixed Rate Link (FRL) features—DP++ cannot be used. In these scenarios, the GPU must output native DisplayPort signals to an active adapter, which utilizes an internal processing chip to unpack the DisplayPort data stream and re-encode it into high-bandwidth HDMI.
