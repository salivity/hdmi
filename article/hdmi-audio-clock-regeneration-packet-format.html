HDMI Audio Clock Regeneration Packet Format

Audio Clock Regeneration (ACR) packets in HDMI are specialized data structures transmitted within Data Island periods to synchronize audio between a source and a sink device. Because HDMI carries audio without a dedicated clock line, it embeds fractional clock synthesis parameters—specifically the Cycle Time Stamp (\(CTS\)) and an integer multiplier/divider (\(N\))—inside these packets. This mechanism enables the sink device to synthesize an audio master clock (\(128 \times f_s\)) directly from the video Transition Minimized Differential Signaling (TMDS) clock with minimal jitter.

Data Island Architecture Context

HDMI transmits video, audio, and control data across three TMDS data channels. During horizontal and vertical blanking intervals, the interface switches to Data Island periods. Each Data Island packet consists of:

  • Header: 4 bytes (3 data bytes plus 1 byte for BCH error correction parity).
  • Packet Body: 32 bytes divided into four 7-byte subpackets (Subpackets 0–3), each followed by BCH ECC parity bits.

ACR Packet Header

The 3-byte header defines the packet type and ensures the receiving device routes the incoming payload to the clock generation Phase-Locked Loop (PLL).

  • HB0 (Packet Type): Set to 0x01 to identify the payload as an Audio Clock Regeneration packet.
  • HB1: Set to 0x00 (Reserved).
  • HB2: Set to 0x00 (Reserved).

ACR Subpacket Body Layout

To maximize reliability and minimize audio clock jitter, all four subpackets (0, 1, 2, and 3) within the 32-byte body carry identical data. If transmission errors corrupt one subpacket, the sink can utilize any of the remaining valid subpackets.

Each 7-byte subpacket encodes a 20-bit \(CTS\) value and a 20-bit \(N\) value formatted as follows:

Byte Offset Bit 7 Bit 6 Bit 5 Bit 4 Bit 3 Bit 2 Bit 1 Bit 0 Description
Byte 0 CTS19 CTS18 CTS17 CTS16 CTS15 CTS14 CTS13 CTS12 Upper 8 bits of \(CTS\)
Byte 1 CTS11 CTS10 CTS9 CTS8 CTS7 CTS6 CTS5 CTS4 Middle 8 bits of \(CTS\)
Byte 2 CTS3 CTS2 CTS1 CTS0 0 0 0 0 Lower 4 bits of \(CTS\) (Bits 3–0 are reserved/0)
Byte 3 N19 N18 N17 N16 N15 N14 N13 N12 Upper 8 bits of \(N\)
Byte 4 N11 N10 N9 N8 N7 N6 N5 N4 Middle 8 bits of \(N\)
Byte 5 N3 N2 N1 N0 0 0 0 0 Lower 4 bits of \(N\) (Bits 3–0 are reserved/0)
Byte 6 0 0 0 0 0 0 0 0 Reserved (Set to 0)

Clock Reconstruction Formula

The receiving device extracts \(N\) and \(CTS\) to drive an internal PLL, reconstructing the target audio sampling frequency (\(f_s\)) using the relationship:

\[128 \times f_s = f_{TMDS\_CLK} \times \frac{N}{CTS}\]

  • \(N\) Value: Predefined by the HDMI specification for standard audio sample rates (e.g., 32 kHz, 44.1 kHz, 48 kHz, 96 kHz, 192 kHz) to ensure optimal PLL operation.
  • \(CTS\) Value: Represents the number of TMDS clock cycles counted during an integer number of audio sample periods.

Coherent vs. Non-Coherent Transmission

  • Coherent Clock Mode: Used when the audio master clock and the video pixel clock derive from a single common oscillator. In this mode, both \(N\) and \(CTS\) remain constant over time.
  • Non-Coherent Clock Mode: Used when the audio and video clocks derive from independent crystal oscillators. Because drift occurs between the clocks, the transmitter dynamically measures the elapsed TMDS cycles and updates the \(CTS\) value in successive ACR packets to reflect slight frequency variations.
