Why HDMI Forum Rejected AMD HDMI 2.1 on Linux

The HDMI Forum officially rejected AMD's request to implement HDMI 2.1 features within its open-source Linux graphics driver due to strict confidentiality and anti-piracy policies. While AMD sought to enable high-bandwidth capabilities such as 4K at 120Hz and 8K at 60Hz for Linux users, the HDMI Forum determined that exposing the required HDMI 2.1 technical specifications in open-source code violates its intellectual property and licensing agreements.

The primary obstacle centers on the proprietary nature of the HDMI specification. Unlike DisplayPort, which is governed by the open VESA standards body, HDMI is managed by the HDMI Forum, a private consortium that requires strict adherence to non-disclosure agreements (NDAs). HDMI 2.1 introduced advanced technologies like Fixed Rate Link (FRL), enhanced Variable Refresh Rate (VRR), and high-bandwidth signaling routines. Under the Forum’s rules, the implementation details and register configurations governing these features cannot be made publicly readable. Because AMD’s standard Linux display driver (AMDGPU) is open source and part of the upstream Linux kernel, publishing the necessary code would inevitably expose the closed HDMI 2.1 specification to the public.

To circumvent this limitation, AMD spent several months collaborating with the HDMI Forum to design a compliant approach. AMD evaluated various technical workarounds, including isolating sensitive components to prevent exposing core intellectual property. However, after extensive review, the HDMI Forum issued a formal rejection, stating that an open-source HDMI 2.1 implementation is fundamentally incompatible with its compliance and security guidelines.

This restriction does not affect closed-source, proprietary software. For instance, NVIDIA can support HDMI 2.1 on Linux because its driver is distributed as a closed binary blob, allowing proprietary code to remain hidden under NDA. Similarly, AMD supports HDMI 2.1 on Windows because the Windows display driver architecture is fully proprietary.

As a consequence of the HDMI Forum's ruling, Linux users running AMD graphics cards cannot utilize native HDMI 2.1 bandwidth, limiting displays connected via HDMI to legacy HDMI 2.0 speeds (typically capping out at 4K at 60Hz). Users seeking higher refresh rates, uncompressed 4K at 120Hz, or 8K resolutions on modern AMD Linux systems must instead use DisplayPort connections or active DisplayPort-to-HDMI 2.1 adapters.
