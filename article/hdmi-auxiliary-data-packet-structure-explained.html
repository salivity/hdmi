HDMI Auxiliary Data Packet Structure Explained

This article provides an overview of the packet structure used for HDMI Auxiliary Data transmission. It examines how auxiliary data—such as multi-channel audio, InfoFrames, and status control signals—is formatted, protected, and transmitted across the HDMI physical link during blanking intervals. You will learn about the standard 32-byte packet layout, including the breakdown of the packet header, subpacket payloads, error correction coding, and physical transmission timing.

The Data Island Transmission Context

HDMI transmits auxiliary data during horizontal and vertical blanking intervals within defined windows called Data Island periods. Unlike standard video pixel data (which uses TMDS 8b/10b encoding), Data Island transmissions use a specialized 4-bit encoding scheme called TERC4 (TMDS Error Reduction Coding).

Each auxiliary data transmission is divided into fixed-size units known as Data Island Packets. Every packet consists of a total of 32 bytes of information, organized into a 4-byte header and four 7-byte subpackets, augmented by dedicated error-correction bits.

Packet Architecture

A complete HDMI Auxiliary Data packet is 32 bytes in size and is structured into two primary components: the Packet Header and the Subpacket Payload.

+-------------------------------------------------------+
|                     Packet Header                     |
|           (3 Bytes Data + 1 Byte BCH Parity)          |
+-------------------------------------------------------+
|  Subpacket 0: 7 Bytes Data + 1 Byte BCH ECC Parity   |
+-------------------------------------------------------+
|  Subpacket 1: 7 Bytes Data + 1 Byte BCH ECC Parity   |
+-------------------------------------------------------+
|  Subpacket 2: 7 Bytes Data + 1 Byte BCH ECC Parity   |
+-------------------------------------------------------+
|  Subpacket 3: 7 Bytes Data + 1 Byte BCH ECC Parity   |
+-------------------------------------------------------+

1. The Packet Header (4 Bytes)

The header defines the type of packet being transmitted and carries packet-specific flags. It consists of:

  • HB0 (Packet Type): An 8-bit unsigned integer defining the payload. Standard types include:
    • 0x01: Audio Clock Regeneration (N/CTS)
    • 0x02: Audio Sample Packet
    • 0x03: General Control Packet (GCP)
    • 0x81–0x85: InfoFrames (Vendor Specific, AVI, Source Product Descriptor, Audio, MPEG Source)
  • HB1 (Header Data 1): 8 bits of payload-specific metadata or control flags.
  • HB2 (Header Data 2): 8 bits of payload-specific metadata or control flags.
  • HB3 (Parity / ECC): An 8-bit parity check code calculated over HB0, HB1, and HB2 using a BCH(32,24) error-correcting code polynomial. This ensures header integrity and allows the receiver to detect and correct single-bit errors or detect multi-bit burst errors.

2. Subpackets (Payload Section)

The payload section is divided into four independent subpackets (Subpacket 0 through Subpacket 3).

  • Data Capacity: Each subpacket contains 7 bytes (56 bits) of data, yielding a total raw payload capacity of 28 bytes per packet.
  • Error Correction Coding (ECC): Each 7-byte subpacket is protected by an appended 8-bit parity field generated via a BCH(64,56) polynomial.
  • Application Flexibility: Depending on the Packet Type, the four subpackets can either be linked together to carry a single large payload (such as an Auxiliary Video Information [AVI] InfoFrame) or used independently to carry concurrent audio data channels (such as multiple L-PCM stereo sample pairs).

Physical Layer Mapping and Transmission Timing

During transmission across the physical TMDS link:

  1. Clock Duration: Each Data Island packet takes exactly 32 TMDS clock cycles to transmit.
  2. Channel Distribution:
    • TMDS Channel 0: Carries the 2-bit horizontal and vertical synchronization signals (HSYNC, VSYNC).
    • TMDS Channel 1: Carries 4 bits per clock cycle via TERC4 encoding, containing the Packet Header bits and Subpacket 0 and 1 streams.
    • TMDS Channel 2: Carries 4 bits per clock cycle via TERC4 encoding, containing Subpacket 2 and 3 streams.
  3. Preamble and Guard Bands: Every Data Island begins with an eight-clock-cycle preamble and a specific two-clock-cycle leading guard band pattern, and terminates with a two-clock-cycle trailing guard band to ensure reliable transition detection between video and auxiliary modes.
