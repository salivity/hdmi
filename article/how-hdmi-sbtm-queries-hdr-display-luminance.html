How HDMI SBTM Queries HDR Display Luminance

Source-Based Tone Mapping (SBTM) is an HDMI 2.1a feature that offloads HDR tone mapping from the display to the source device, such as a PC or gaming console. To tone-map content accurately, the source must retrieve the physical capabilities of the connected display. This article explains the technical mechanism an HDMI SBTM source uses to query and interpret the exact luminance boundaries—including minimum black levels, peak luminance, and full-frame white levels—from an HDR display.

The Handshake via the Display Data Channel

When an HDMI source connects to an HDR display, it initiates a hardware handshake across the I2C-based Display Data Channel (DDC). The source issues a read request to access the display's Enhanced Extended Display Identification Data (E-EDID).

The base EDID standard only provides basic timing and display identification. Therefore, luminance characteristics and modern HDR features are encapsulated within CTA-861 extension blocks appended to the base EDID structure.

The CTA-861 SBTM Data Block

HDMI 2.1a relies on the CTA-861-H standard, which defines a dedicated SBTM Data Block. During the EDID read cycle, the source parses the extension blocks specifically looking for the SBTM Data Block tag.

If present, this block indicates that the display supports SBTM and provides explicit parameters defining the display's panel performance. Unlike traditional HDR10 setups that often rely on static mastering metadata (SMPTE ST 2086) negotiated broadly, the SBTM Data Block conveys exact hardware metrics measured or calibrated by the display manufacturer.

The Queried Luminance Parameters

Within the SBTM Data Block, the display provides three critical luminance parameters:

  1. Minimum Luminance (\(Min\_Lum\)): Defines the black floor of the display, indicating how deep the display's black levels can reach before shadow detail is crushed.
  2. Maximum Peak Luminance (\(Max\_Lum\)): Defines the maximum brightness the panel can produce over a small percentage of the screen area (such as a 10% window). This dictates the ceiling for specular highlights.
  3. Maximum Full-Frame Luminance (\(Max\_FALL\_Lum\)): Defines the sustained luminance the display can produce across the entire screen simultaneously. This is critical for displays subject to Automatic Brightness Limiting (ABL), such as OLEDs.

These values are typically encoded using defined numerical steps (often utilizing non-linear coding curves such as the Perceptual Quantizer to represent a wide dynamic range in fewer bytes).

Processing and Tone Mapping Execution

Once the source reads and decodes the SBTM Data Block:

  1. Boundary Registration: The source’s graphics pipeline registers the exact minimum, peak, and full-frame luminance targets.
  2. Internal Composition: The source composites mixed content (such as an SDR user interface overlaid on an HDR game window) and maps all pixels into the target luminance container defined by the display's reported boundaries.
  3. Transmission: The mapped frames are sent across the HDMI interface. Because the content has been pre-conditioned to match the panel's physical limits, the display bypasses its own internal tone mapping curves, eliminating clipping, color shifting, and excessive latency.
