Custom Resolution Utility and HDMI Descriptor Blocks

Custom Resolution Utility (CRU) is a lightweight Windows software application designed to modify display parameters by creating software-level Extended Display Identification Data (EDID) overrides directly within the operating system registry. Rather than flashing the physical firmware of a monitor or television, CRU alters how the graphics driver interprets a display's capabilities, specifically targeting CTA-861 extension blocks where HDMI-specific descriptors reside. This article explains what CRU is, how EDID communication functions, and the precise technical mechanisms CRU uses to manipulate HDMI display descriptor blocks to unlock custom resolutions, refresh rates, FreeSync ranges, and color formats.

What is Custom Resolution Utility?

Custom Resolution Utility is a specialized tool developed by ToastyX that allows users to define custom display resolutions, adjust detailed timing parameters, and configure advanced display capabilities. When a monitor connects to a PC via HDMI or DisplayPort, it transmits a standardized data structure called EDID to the graphics processing unit (GPU). The operating system and GPU drivers read this metadata to determine supported resolutions, refresh rates, color spaces, and audio formats.

CRU intercepts this process. Instead of modifying the physical EEPROM chip on the display, CRU writes synthetic EDID data to the Windows Registry. When the graphics driver initializes, it reads the registry override instead of the raw data supplied by the monitor, allowing users to bypass vendor-imposed software limitations.

Understanding EDID and HDMI Extension Blocks

A standard EDID structure consists of a base 128-byte block. Because legacy EDID architecture predates modern digital display standards like HDMI and DisplayPort, it contains limited space for advanced features. Modern displays use extension blocks to provide supplementary metadata.

HDMI features are defined in the CTA-861 (formerly CEA-861) Extension Block, which typically occupies a second 128-byte block (or multiple blocks). Within this extension block lies the Data Block Collection (DBC), which stores specialized descriptor payloads, including:

  • HDMI Vendor-Specific Data Block (HDMI VSDB): Identified by the IEEE Registration Identifier 0x000C03, this block specifies HDMI 1.4b capabilities, including maximum TMDS clock rates, 3D video formats, deep color support (10-bit, 12-bit), and latency compensation.
  • HDMI Forum Vendor-Specific Data Block (HF-VSDB): Identified by the IEEE Registration Identifier 0xC45DD8, this block handles HDMI 2.0+ and 2.1 features, including 4K at 60Hz/120Hz support, scrambling, Status and Control Data Channel (SCDC), Variable Refresh Rate (VRR), and Auto Low Latency Mode (ALLM).
  • Video Data Blocks (VDB): Define standard CEA resolutions and timings (e.g., 1080p at 60Hz, 4K at 60Hz).
  • Audio Data Blocks: Specify supported audio formats (such as LPCM, Dolby Digital, or DTS) and channel counts.
  • Colorimetry Data Blocks: Define wide color gamuts such as BT.2020 and HDR metadata handling.

How CRU Manipulates HDMI Display Descriptor Blocks

CRU allows users to surgically modify, add, or delete the descriptor blocks within the CTA-861 extension. It manipulates this data through several precise steps:

1. Ingesting and Parsing Display Descriptors

When launched, CRU queries the graphics driver via the Windows Application Programming Interface (API) to extract the active EDID block hierarchy. It decodes the raw binary data into human-readable parameters, separating the base EDID from extension blocks.

2. Modifying the HDMI Vendor-Specific Payloads

CRU provides a graphical interface that maps directly to the bitmasks and bytes of the HDMI VSDB and HF-VSDB:

  • Clock Limit Adjustments: CRU allows users to modify the maximum TMDS clock rate field. Raising or lowering this value signals to the GPU whether the HDMI link can handle higher data throughput, enabling higher refresh rates or higher resolutions over an existing HDMI port.
  • Variable Refresh Rate (VRR) / FreeSync Ranges: Within the vendor-specific data blocks, display manufacturers declare the minimum and maximum operational refresh rates for adaptive sync. CRU allows users to directly edit these integers (e.g., changing a 48–60Hz range to 35–60Hz), extending the functional operational window of adaptive synchronization.
  • Feature Flag Toggling: CRU alters specific bit flags within the descriptor payload, toggling support for Deep Color (YCbCr 4:2:0/4:4:4, 10/12-bit), HDMI 2.0 SCDC operational modes, and HDR signaling.

3. Reconstructing and Validating Extension Blocks

Once modifications are applied, CRU re-encodes the structured parameters back into raw byte arrays conforming to the CTA-861 specification. As part of this process:

  • It updates the Data Block Collection header bytes, which contain the block type and payload length tags.
  • It automatically recalculates the checksum byte located at byte offset 127 of the extension block. If the sum of all 128 bytes in the block does not equal zero modulo 256, the GPU driver will reject the EDID as corrupt and fall back to safe generic timings (typically 640x480 or 1024x768). CRU ensures the checksum is consistently valid.

4. Injecting the Overrides into the Windows Registry

CRU does not interact with the monitor directly; it operates on the driver level. Upon saving, CRU writes the modified binary blocks to the following registry path:

HKLM\SYSTEM\CurrentControlSet\Enum\DISPLAY\[Monitor Hardware ID]\[Device Instance]\Device Parameters

Under this key, CRU creates or modifies a binary value named EDID.

5. Driver Re-enumeration

To apply the changes, CRU includes a helper utility called restart.exe, which issues a reset command to the graphics display subsystem (DWM and the graphics kernel driver). When the GPU driver reloads, it queries the hardware registry key, detects the newly written EDID override value, and parses the synthetic HDMI descriptor blocks instead of requesting physical data across the I2C/DDC channel of the HDMI cable. As a result, the graphics driver immediately exposes the new resolutions, refresh rates, and feature sets defined by the user.
