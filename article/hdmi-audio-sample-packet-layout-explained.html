HDMI Audio Sample Packet Layout Explained

This article details the exact technical structure and byte layout of the Audio Sample Packet defined in the legacy HDMI 1.0 through 1.4 specifications. It covers the 3-byte packet header fields, the subpacket byte assignments, the operational differences between Layout 0 and Layout 1, and the mapping of IEC 60958 channel status and control bits.

Overview and General Structure

HDMI transmits audio during the Data Island period using dedicated packets. Each Audio Sample Packet has a packet type code of 0x02 and consists of:

  • A 3-byte Packet Header (accompanied by a BCH ECC parity byte generated at the physical layer).
  • Four Subpackets, each containing 7 bytes of audio data (28 payload bytes total), each protected by its own BCH ECC sequence.

The packet encapsulates L-PCM or compressed audio streams formatted according to the IEC 60958 or IEC 61937 standards at sample rates ranging from 32 kHz to 192 kHz.

Packet Header Byte Definition

The 3-byte header configures how the sink device decodes the subpackets:

Header Byte 0 (HB0)

  • Bits [7:0]: Packet Type Value (0x02), identifying the packet as an Audio Sample Packet.

Header Byte 1 (HB1)

  • Bits [3:0] – sample_present.spX: Four flags (sp0, sp1, sp2, sp3) indicating whether Subpacket 0, 1, 2, or 3 contains active audio data (1 = active, 0 = empty).
  • Bit [4] – layout: Defines the channel allocation layout:
    • 0: Layout 0 (2-channel audio).
    • 1: Layout 1 (multi-channel audio, up to 8 channels).
  • Bits [7:5]: Reserved (set to 0).

Header Byte 2 (HB2)

  • Bits [3:0] – sample_flat.sfX: Four flags (sf0, sf1, sf2, sf3) indicating whether the sample in the corresponding subpacket represents a flatline (muted or zero-amplitude) condition (1 = flat sample, 0 = normal sample).
  • Bits [7:4]: Reserved (set to 0).

Layout Modes: Layout 0 vs. Layout 1

The HDMI specification defines two operational layouts dictated by the layout bit in HB1:

Layout 0 (Two-Channel Audio)

  • Used for standard stereo L-PCM or 2-channel IEC 61937 bitstreams.
  • The packet carries up to four consecutive temporal samples for the same 2-channel pair.
  • Subpacket 0: Sample \(t\)
  • Subpacket 1: Sample \(t+1\)
  • Subpacket 2: Sample \(t+2\)
  • Subpacket 3: Sample \(t+3\)
  • Any combination of subpackets may be flagged as present via sp[3:0], allowing variable sample transmission rates per horizontal line.

Layout 1 (Multi-Channel Audio)

  • Used for 3-channel to 8-channel audio configurations.
  • The packet carries exactly one temporal sample across up to four stereo channel pairs.
  • Subpacket 0: Channel Pair 0 (Channels 1 & 2 / Front Left & Front Right)
  • Subpacket 1: Channel Pair 1 (Channels 3 & 4 / Center & LFE)
  • Subpacket 2: Channel Pair 2 (Channels 5 & 6 / Rear Left & Rear Right)
  • Subpacket 3: Channel Pair 3 (Channels 7 & 8 / Rear Center or Side channels)
  • Subpacket presence flags must reflect contiguous channel allocations starting at Subpacket 0.

Subpacket Data Layout

Each of the four 7-byte subpackets carries two channels of audio data (designated Channel A and Channel B) formatted identically to an IEC 60958 sub-frame pair:

  • Byte 0: Channel A Audio Sample Word, bits [7:0]
  • Byte 1: Channel A Audio Sample Word, bits [15:8]
  • Byte 2: Channel A Audio Sample Word, bits [23:16]
  • Byte 3: Channel B Audio Sample Word, bits [7:0]
  • Byte 4: Channel B Audio Sample Word, bits [15:8]
  • Byte 5: Channel B Audio Sample Word, bits [23:16]
  • Byte 6: IEC 60958 Control and Status Bits

If the audio word length is less than 24 bits (e.g., 16-bit or 20-bit audio), the data is left-aligned to bit 23, and the unused least significant bits in Byte 0 and Byte 3 are padded with zeros.

Subpacket Byte 6 Bit Allocation

Byte 6 contains the channel status, validity, user, and parity bits for both Channel A and Channel B:

Bit Identifier Description
Bit 0 \(V_A\) Validity bit for Channel A (0 = reliable data, 1 = defective/unsuitable)
Bit 1 \(V_B\) Validity bit for Channel B (0 = reliable data, 1 = defective/unsuitable)
Bit 2 \(U_A\) User data bit for Channel A
Bit 3 \(U_B\) User data bit for Channel B
Bit 4 \(C_A\) Channel Status bit for Channel A
Bit 5 \(C_B\) Channel Status bit for Channel B
Bit 6 \(P_A\) Parity bit for Channel A (even parity over bits [23:0] and \(V, U, C\))
Bit 7 \(P_B\) Parity bit for Channel B (even parity over bits [23:0] and \(V, U, C\))

The Channel Status bits (\(C_A, C_B\)) are collected sequentially over 192 frames to assemble the complete 192-bit IEC 60958 Channel Status block, conveying metadata such as sample frequency, word length, and copyright protection parameters.
