How an OS Queries HDMI Audio Channels

When a display or AV receiver connects via HDMI, the operating system discovers the available audio channels by reading the sink device's Extended Display Identification Data (EDID) through the graphics driver. Specifically, the OS uses the I2C-based Display Data Channel (DDC) to read the CTA-861 extension block within the EDID, parsing the Audio Data Block (ADB) and Speaker Allocation Data Block (SADB). This handshake allows the audio subsystem to identify the maximum supported channel count, channel layouts, and audio formats, configuring the output device accordingly without requiring manual user intervention.

1. The Physical Handshake and DDC Bus

The discovery process begins the moment an HDMI cable is connected:

  1. Hot Plug Detect (HPD): The sink device (such as a TV, monitor, or AV receiver) raises the 5V Hot Plug Detect pin to signal its presence to the source device (the computer).
  2. Reading EDID via I2C: The host computer’s GPU detects this voltage transition and initiates a read operation over the Display Data Channel (DDC), an I2C-based serial communication link running within the HDMI cable.
  3. Fetching the Base EDID: The GPU queries the standard 128-byte base EDID block stored in the display's EEPROM, which contains fundamental information about the display's manufacturer, resolution limits, and timing capabilities.

2. Inspecting the CTA-861 Extension Block

Base EDID alone only details video information. To determine audio capabilities, the operating system's display driver checks for the presence of extension blocks:

  • The display provides one or more 128-byte CTA-861 (formerly CEA-861) extension blocks designed specifically to describe consumer electronics features like HDMI digital audio.
  • Within the CTA-861 extension, the driver locates the variable-length Data Block Collection, which contains categorized tags for video, audio, and vendor-specific data.

3. Parsing the Audio Data Block (ADB)

The driver searches the Data Block Collection for the Audio Data Block (ADB), identified by the tag value 1. Inside this block are one or more 3-byte structures called Short Audio Descriptors (SADs):

  • Format Type: Each SAD defines a supported audio format, such as uncompressed Linear PCM (LPCM), AC-3 (Dolby Digital), DTS, or Dolby TrueHD.
  • Channel Capacity: Bits 0 to 2 of the first byte in an LPCM SAD encode the maximum number of audio channels supported for that format:
    • 000b = 1 channel (Mono)
    • 001b = 2 channels (Stereo)
    • 010b = 3 channels
    • 011b = 4 channels (Quadraphonic)
    • 100b = 5 channels
    • 101b = 6 channels (5.1 surround)
    • 110b = 7 channels
    • 111b = 8 channels (7.1 surround)
  • Higher Channel Counts (HDMI 2.0+): Modern standards use 3D Audio and Multi-Stream Audio descriptors within CTA-861 extensions to communicate support for setups exceeding 8 channels, such as 32-channel spatial audio.

4. Reading the Speaker Allocation Data Block (SADB)

Knowing only the total channel count is insufficient; the operating system must also know the physical placement of those channels. For this, it parses the Speaker Allocation Data Block (tag 4):

  • The SADB contains a 3-byte payload where individual bits map directly to physical speaker locations (e.g., Front Left/Right, Low-Frequency Effects/Subwoofer, Front Center, Rear Left/Right, Side Left/Right, and presence speakers).
  • By cross-referencing the channel count from the SAD with the bitmask from the SADB, the operating system can map surround sound configurations precisely (such as differentiating between a 5.1 layout using surround rears versus surround sides).

5. Passing Data from Driver to OS Audio Subsystem

Once the graphics hardware and driver assemble these capabilities:

  1. GPU Audio Controller Binding: Most modern GPUs integrate an Intel High Definition Audio (HDA)-compliant controller. The GPU driver passes the parsed channel metadata to this internal audio controller.
  2. Audio Subsystem Registration: The OS audio subsystem—such as Windows Audio Session API (WASAPI) and Core Audio on Windows, ALSA and PulseAudio/PipeWire on Linux, or CoreAudio on macOS—creates an audio endpoint representing the HDMI output.
  3. Endpoint Configuration: The subsystem sets the default channel count and format based on the highest standard capability negotiated (typically multi-channel LPCM if supported, or falling back to 2-channel stereo).

Applications querying the operating system for output capabilities can then retrieve the exact number of channels supported by the receiving HDMI hardware.
